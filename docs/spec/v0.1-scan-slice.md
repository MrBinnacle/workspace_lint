## 1. Scope

### 1.1 What the slice does

One command. One declared root. Two rules — `SYS001` and `REF001`. One coverage manifest. One
Markdown report, one JSON report, one exit byte.

**Revisable — the two-rule scope.** `REF001` is in because `CONTEXT.md` settled defaults name it the
**load-bearing coverage mechanism**: a link is the only surviving trace of an inaccessible resource,
which the 2026-08-17 proof run established when a `child_page` block vanished from its parent's
child list. `SYS001` is in because it is the finding identity for a coverage gap and every other
rule depends on the manifest it reports against. *Revisit if:* building `REF001` shows the manifest
is unusable without `REQ001`'s property hydration, which would mean the funnel's `fetched` stage is
under-specified rather than that the scope is wrong.

### 1.2 What the slice does not do

- No `REQ001`, no `UNQ001`, no deferred rule.
- No baseline file, no suppressions. Every finding in this slice is `new` by construction. ADR-0008
  decision 1's five baseline states are **not** exercised here, and the slice must not pretend
  otherwise by printing a state it did not compute.
- No CI mode. `CONTEXT.md` settled defaults put the local CLI first.
- No write of any kind. Principle 7.

### 1.3 The slice does not close #10, and saying so is the point

Issue #10's fixture seeds defects for all eight rules, and its proof checks include *"detect every
seeded confirmed defect"* and *"run `REQ001` against the current Directory."* Two rules cannot
satisfy those. **This slice is stage 1 of #10.** #10 closes when the remaining shipping rules land
against the same fixture and the full check list passes.

State this in the recorded result. A slice reported as closing #10 would be a coverage claim over an
unrun set, which is the defect class this product exists to detect.

## 2. Acceptance criteria

Nine criteria. Numbers 1–9 map to issue #10's proof checks in order. Each names what governs it and
what the slice narrows.

**1. Enumerate the declared root and match a hand-written manifest.** *Non-negotiable —
ADR-0002 decisions 1 and 2.* Coverage is measured against declared roots, never against the
workspace. The hand-written manifest is the test oracle and must be written **before** the run.

**2. Retrieve nested block trees to the depth `REF001` requires.** *Non-negotiable —
`CONTEXT.md` settled defaults, "the block crawl is selective, not metadata-only."* Narrowed for the
slice: schemas, rows and long relation values are `REQ001`/`UNQ001` concerns and are out of §1.2.
Block content is in, because `REF001` reads hyperlinks inside blocks.

**3. Detect every seeded `SYS001` and `REF001` defect.** *Revisable — the narrowing.* #10 says
"every seeded confirmed defect" across eight rules; this slice covers two. The report must name the
seeded defects it did **not** look for, so the gap between this run and #10 is legible.

**4. Label the unshared target `indeterminate`, not broken.** *Non-negotiable — Principle 3,
`CONTEXT.md`'s "confirmed is not indeterminate."* An unconnected page returns **404, not 403**
(observed 2026-08-17). Access failure and object absence share a response. A `REF001` finding
against it is `certainty: indeterminate` with `target state: unreachable` — and per `CONTEXT.md`,
a finding can be **`confirmed` about an `unreachable` target**, so do not collapse the two axes.

**5. Emit one readable Markdown report and one stable JSON report.** *Non-negotiable — ADR-0004.*
Stable means byte-identical across two runs over an unchanged workspace, after the named
Normalization function strips volatile fields. Determinism is defined against Normalization's
output, never against the raw response.

**6. Publish the coverage manifest as a vector, never as one pooled figure.** *Non-negotiable —
ADR-0011, and ADR-0005 decision 4's prohibition on publishing a ratio alone.* The manifest carries
the five funnel stages — declared, resolved, enumerated, fetched, evaluated — and **each rule's own
coverage item**: `SYS001` counts resources, `REF001` counts internal references. Two rules means a
two-entry vector. **The headline is the minimum, never a mean**, and no figure is printed without
its unit named. Every drop-out names a resource and a specific cause.

**7. Return exit `2` after a seeded pagination or retrieval failure.** *Non-negotiable — ADR-0008
decision 2 (precedence 4 > 2 > 3 > 1 > 0) via ADR-0005's pervasiveness predicate.* A seeded failure
inside a declared root produces a gap the scan cannot size — an **unbounded** gap — which makes the
gap set **Pervasive**, which makes the report disposition **`disclaimed`**, which renders no summary
verdict and exits `2`. Verify the whole chain fires, not just the byte. **An exit `2` reached by any
other path is a different bug wearing the right number.**

**8. Complete the scoped run within the stated budget.** *Revisable — the figure.* `store.json`
records the standing sizing figure: **3 requests per second per connection**, making a three-minute
warm scan a budget of roughly 540 requests. #10 says two minutes for the Directory scan. Record the
actual request count and wall time; do not treat either number as validated until #7 sets budgets on
a named reference workspace.

**9. Persist no token and no page-body text.** *Non-negotiable — Principles 6 and 7, and the
existing discipline on `proto/ref001-observed`.* `prototypes/live-ref001.ts` routes every line
through a `scrub()` and sets the SDK's `logLevel: 'error'`, because the SDK's own warn logger
bypasses application redaction. Reuse that, do not re-derive it. Page titles are redacted by default
per `CONTEXT.md` settled defaults.

## 3. Two disclosures the report must carry

**3.1 Blind endpoints.** *ADR-0006 decision 5.* `GET /v1/blocks/{id}/children` carries **no**
truncation signal. A complete enumeration and a silently truncated one both return `has_more: false`.
The traversal spine of this scan is therefore trusted blind, and the report discloses that per run
rather than hiding it. Corroborated by `notion-sdk-js` PR #711 omitting `ListBlockChildrenResponse`.

**3.2 The truncation test is positive-only.** *ADR-0006 decision 1.* Test for
`request_status.type === 'incomplete'`. **Absence is neither an error nor proof of completeness**,
and maps to `sufficient`. `request_status` has never been observed on any endpoint on either branch,
so **no code path may block on its arrival.**

## 4. The red test

Before the slice is believed, it must fail correctly.

**4.1 The mutation check is mandatory.** A control that passes with its mechanism bypassed tested
nothing. `prototypes/CHECK-link-recognition.ts` already carries one; this slice carries its own.
Disable the coverage-gap detection and criterion 7 must go red. If it stays green, the suite is
measuring nothing.

**4.2 The specific false-green to hunt.** Run against a declared root whose child list is
permission-filtered. The vanished child cannot be counted, named, or reported — observed
2026-08-17. Confirm the manifest does **not** report full coverage over that root. `REF001` is what
catches it, via a surviving link, and that is why `REF001` is in the slice.

## Revisit if

**The slice cannot produce a coverage manifest against declared roots without write access or an
LLM.** That is the project's stop condition, stated in `CONTEXT.md` and `PRODUCT.md`. It has not
fired. This slice is the first artefact capable of firing it.

**`REF001` stops being load-bearing.** If Notion ships an endpoint that enumerates a connection's
grant, coverage no longer rests on link resolution and §1.1's scoping argument dissolves. Not
announced. Carried forward from issue #18.
